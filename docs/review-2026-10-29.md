Проверены портфолио, TraceShelf, QuietSlot, RePair Atlas, импорт и экспорт, локальное хранение, сборки и GitHub Actions. Подтверждённых Critical/High уязвимостей в проверенном коде не найдено. Найденные ниже ошибки логики, сохранности данных и интерфейса исправлены.

## Исправленные ошибки

### R01 · Medium · TraceShelf: ложная актуальность после удаления доказательства

Место: `projects/traceshelf/app/src/model.ts`, функции `getHealth`, `saveEntry`, `addDependency`, `removeDependency`, `deleteEntry`, `reviewEntry`.

До исправления `evidenceChanged` учитывал только `title`, `body`, `url`. Удаление одного из двух источников не меняло ревизию утверждения; проверка актуальности обходила только оставшихся предков. Утверждение и решение могли оставаться актуальными без пересмотра.

Теперь смена состава связей увеличивает ревизию и устанавливает `needsReview`; подтверждение снимает этот флаг только после проверки зависимостей. `getHealth` также выявляет прежних предков, исчезнувших из снимка v1. Исходный формат v1 продолжает читаться. Тест проверяет удаление связи через форму, отдельное действие, удаление источника и старый снимок без нового флага.

Ключевые строки: [проверка статуса](../projects/traceshelf/app/src/model.ts#L195), [сохранение](../projects/traceshelf/app/src/model.ts#L277).

### R02 · Medium · QuietSlot и RePair Atlas: потеря новых изменений из другой вкладки

Место: `projects/quietslot/app/src/store.ts:39`, `projects/repair-atlas/app/src/store.ts:30`.

Раньше `localStorage.setItem` записывал весь снимок из памяти без сравнения с хранилищем. Вкладка со старым состоянием могла заменить более свежий план. Теперь перед записью проверяется `localStorage.getItem(STORAGE_KEY) !== lastStored`. При несовпадении запись отклоняется, пользователь получает указание перезагрузить страницу, новый снимок остаётся целым. Регрессия проверена и модульно, и двумя реальными страницами одного браузерного контекста.

Это оптимистическая проверка, а не транзакционная блокировка: строго одновременные записи между сравнением и `setItem` по-прежнему требуют транзакционного хранилища или отдельной координации. Совместное редактирование не заявляется.

### R03 · Low · Портфолио: ошибка при запрете сохранения темы

Место: `apps/portfolio/src/store.ts:19`.

Исключение `SecurityError`/ошибка квоты из persist могло выйти из обработчика переключения темы. Добавлен защищённый адаптер `createJSONStorage`. Тема работает в памяти, даже если браузер запретил сохранение настройки. Тест проверяет отказ чтения/записи без ошибок JavaScript.

### R04 · Medium · Читаемость: недостаточный контраст текста

Место: `apps/portfolio/src/styles.css`, `projects/{traceshelf,quietslot,repair-atlas}/app/src/styles.css`.

axe обнаружил контраст ниже 4.5:1 у мелких подписей: например, QuietSlot `#938b7b` на `#faf9f5` давал 3.2:1; TraceShelf `#716b85` на `#252434` — около 3:1. Изменены цвета текста на светлых поверхностях и тёмной боковой панели, включая историю и пояснения. Обновлены реальные скриншоты трёх приложений в портфолио.

Тесты axe используют `wcag2a`, `wcag2aa`, `wcag21aa` для главных экранов, страниц проектов, истории QuietSlot, сравнения, матрицы и прохождения RePair Atlas; проверяется и тёмная тема портфолио. Переходы отключены в этой статической проверке, чтобы не измерять промежуточный цвет анимации. Автоматическая проверка не заменяет полный аудит WCAG.

### R05 · Medium · RePair Atlas: длинный шаг ломал мобильную вёрстку

Место: `projects/repair-atlas/app/src/styles.css:710`, `:1203`.

Название из 80 букв без пробелов растягивало страницу шириной 390 px до 1074 px. Добавлены `min-width: 0` и `overflow-wrap: anywhere` для названий в редакторе маршрута и прохождении. Регрессионный сценарий использует ширину 320 px, а также длинные имена QuietSlot и записи/владельцев TraceShelf.

## Безопасность

- Пользовательский текст выводится через JSX. Не обнаружены рабочие `dangerouslySetInnerHTML`, `innerHTML`, `eval` или `new Function`. Браузерный тест с `<img src=x onerror=alert(1)>` подтверждает вывод буквального текста во всех трёх проектах, без создания изображения и диалога.
- TraceShelf проверяет протокол ссылок: разрешены http(s), `javascript:` отклоняется; внешние источники используют `noopener noreferrer`.
- Все четыре production-сборки имеют meta-CSP: `script-src 'self'`, без `unsafe-inline` и `unsafe-eval`, с ограничениями объектов, base URI и отправки форм. Тест реально добавляет inline-script и проверяет, что он не исполняется.
- JSON проверяется до замены данных. Лимиты импорта: TraceShelf 1 МБ / 200 записей / 800 связей; RePair Atlas 256 КБ / 30 шагов. Некорректный JSON, циклы и нарушенные ссылки отклоняются; ошибки квоты не уничтожают предыдущий снимок.
- ICS использует UTC, экранирование текста и перенос строк по октетам UTF-8; независимый парсер проверяет результат. Встречи не отправляются другим людям.
- Поиск характерных шаблонов ключей/секретов в исходниках и CI не дал совпадений. Клиент не содержит авторизации, секретных API или серверных операций. Разные ключи localStorage разделяют данные приложений, но не создают границу безопасности внутри общего origin.
- CI использует `npm ci`, закреплённые SHA действий, `contents: read`, отключённое сохранение Git credentials; права `pages: write` и `id-token: write` выдаются только deploy-job. `npm audit` после добавления средства проверки доступности: 0 известных уязвимостей на момент проверки.

## Остаточное ограничение хостинга · Low

Публичный ответ Pages при проверке не содержал HTTP-заголовков CSP, X-Frame-Options, X-Content-Type-Options и Referrer-Policy; CSP задаётся HTML-метатегом в Vite-конфигурациях. `frame-ancestors` через meta не поддерживается: [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors). Поэтому защита от встраивания в чужой iframe не обеспечена. Для её добавления нужен управляемый слой HTTP-заголовков перед Pages либо другой хостинг; JavaScript-проверка родительского окна не подменяет такую защиту. Хостинг и инфраструктура в рамках этого обновления не менялись.

localStorage может быть недоступен из-за политики браузера: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage). Это учтено обработчиками ошибок. Данные локальных MVP не зашифрованы и исчезают при очистке хранилища; JSON служит резервной копией.

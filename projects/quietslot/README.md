# QuietSlot

Рабочий локальный MVP планировщика встреч для распределённых команд. Подбирает время, показывает неудобство для каждого участника и учитывает нагрузку из сохранённой истории.

## Запуск

Из корня репозитория: `npm ci`, затем `npm run dev:quietslot` (порт 4190). Общая production-сборка: `npm run build`, просмотр: `npm run preview`, маршрут `/quietslot/`.

## Возможности

- Своя команда из 1–8 участников или два явно обозначенных вымышленных демосценария.
- IANA-пояса, рабочие дни, окна через полночь, строгая доступность и исключённые локальные даты.
- Разовая встреча или 2–4 еженедельных встречи; длительность 15–120 минут, поиск на 1–7 дней.
- Топ вариантов, тепловая карта и таблица, объяснение оценки, сравнение разовой встречи и серии.
- История до 100 встреч со снимками имён и нагрузки; её пересечения исключаются из нового подбора.
- Экспорт отдельных UTC-событий в ICS. Экспорт не добавляет запись в историю.
- Локальное сохранение команды, настроек и истории; ошибки чтения и записи видимы пользователю.

## Стек и расчёт

React, TypeScript, Vite, React Router, Tailwind, React Hook Form, Zod. Zustand владеет редактором и localStorage; React Query загружает демосценарии через адаптер. Серверного API нет.

Часовые пояса обрабатывает `@js-temporal/polyfill`. Моменты встреч сохраняются в UTC; IANA-пояса — отдельно. Недельная серия сохраняет локальный час организатора, а не фиксированное смещение UTC. Неоднозначные или несуществующие старты последующих недель исключаются. Повторяющийся час первого дня представлен разными UTC-слотами с подписями смещений. Модель соответствует правилам [Temporal](https://tc39.es/proposal-temporal/docs/zoneddatetime.html).

Рассматриваются старты с шагом 30 минут, доступность проверяется каждые 15 минут реального времени. Рабочее окно через полночь принадлежит дню его начала. Строгие окна, исключённые даты и пересечения истории не ослабляются. Ночные часы внутри рабочего окна не штрафуются.

Базовый штраф участника: `100 × доля минут вне рабочего окна + 50 × доля ночных минут вне окна` (ночь 22:00–07:00). При учёте истории прибавляется `штраф × min(накопленная нагрузка, 10) × 0.25`; нагрузка равна сумме прежних штрафов / 100. В серии нагрузка накапливается после каждой встречи. Итог усредняется по участникам и встречам; при равенстве раньше идёт более ранний UTC-слот. Это ранжирование дискретных вариантов, математическая оптимальность не заявляется.

## Проверки

`npm run check`, `npm run build`, `npm run test:e2e` запускаются из корня. Модульные проверки покрывают DST, разные локальные даты, ночные окна, строгие ограничения, справедливость, пересечения и сохранённые снимки. ICS разбирается независимым парсером `ical.js`, включая UTC, переносы UTF-8 и экранирование. Браузерные сценарии проверяют формы, свою команду, сравнение, серию, загрузку ICS, историю после перезагрузки, клавиатуру, переход из портфолио и ширины 320 / 390 / 768 / 1440.

## Границы MVP

Данные остаются в текущем браузере и могут исчезнуть при очистке его хранилища. Нет аккаунтов, совместного редактирования и синхронизации календарей. ICS не отправляет приглашения; импорт в конкретные внешние календарные приложения вручную не проверялся. Правила часовых поясов зависят от базы Intl браузера; исторические переходы вне четвертьчасовой сетки не гарантируются. Проверки Playwright выполняются в Chromium, включая мобильную эмуляцию.

# Модель и решения

## Инварианты

Снимок схемы v1 содержит nodes и edges. Связь from → to означает «to основано на from». Источник не имеет входящих связей. Перед любой записью Zod проверяет поля, затем проверяются уникальность ID, существование концов связей, дубликаты и отсутствие циклов алгоритмом Кана.

У каждой записи есть revision. Изменение названия, контекста или URL повышает версию; смена владельца не меняет доказательства. При подтверждении reviewedVersions сохраняет версии всех предков. Новая запись с зависимостями получает исходный снимок версий, но не может скрыть уже проблемные зависимости.

## Пересмотр

- Источник становится устаревшим, когда checkedAt + freshForDays <= текущая календарная дата.
- Проверка «сегодня» обновляет дату, не меняя версию содержимого.
- Утверждение/решение без достижимого первоисточника получает статус «Нет источников».
- Новая/изменившаяся версия предка, устаревший источник или неподтверждённое промежуточное утверждение переводят запись на пересмотр.
- Подтверждение возможно только при актуальных непосредственных зависимостях и наличии источника в цепочке.

Панель причин использует один кратчайший путь к каждому предку. Все возможные пути не перечисляются: в DAG их число может расти экспоненциально. Вычисление статусов кешируется на время обхода, а в React — по снимку данных и дате. Дата обновляется не реже раза в минуту.

## Сохранность и безопасность

Адаптер читает текущий снимок перед мутацией и записывает его одним localStorage.setItem только после полной проверки. Неудачный импорт, цикл и ошибка квоты не заменяют прежний снимок. Повреждённое хранилище не перезаписывается демонабором автоматически.

Импорт требует подтверждения замены данных. Файл ограничен 1 МБ до чтения; схема — 200 записями и 800 связями. Ссылки принимают только http(s), текст отображается через JSX. Нет HTML-инъекций, внешних скриптов и сетевых запросов с пользовательскими данными. Production использует CSP без unsafe-inline/unsafe-eval.

## Сборка и портфолио

`scripts/build.mjs` собирает два независимых Vite-приложения и копирует TraceShelf в `apps/portfolio/dist/traceshelf/`. Оба используют относительные ресурсы и HashRouter. CI и деплой проверяют собранный сайт с одним production preview.

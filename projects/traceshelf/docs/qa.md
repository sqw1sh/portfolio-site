# Проверки TraceShelf

## Автоматические сценарии

14 модульных проверок TraceShelf покрывают транзитивные причины пересмотра, порядок подтверждения, границу срока, циклы/самоссылки/дубликаты, изменение содержимого и владельца, новые зависимости, удаление источника, ромбовидный граф, URL/даты/ID, импорт, повреждённое хранилище, квоту и размер файла.

Пять браузерных сценариев повторяются в desktop Chromium и мобильной эмуляции:

1. Источник → утверждение → решение → изменение источника → последовательный пересмотр → обновление страницы.
2. Таблица, поиск и фильтры, клавиатурное открытие, отклонение цикла, удаление связи и запрет подтверждения без источника.
3. Неверный JSON без потери данных, экспорт, пустое пространство и восстановление из файла.
4. Валидация формы, недопустимый URL, смена типа, удаление записи и ширины 320/390/768/1440.
5. Переход из реальной карточки портфолио в рабочий MVP.

Вместе с портфолио: 20 модульных/компонентных и 20 E2E-проверок. Для E2E предварительно нужна полная сборка.

```sh
npm run check
npm run build
npm run test:e2e
```

Регрессия мобильной таблицы: absolute-подпись sr-only должна оставаться внутри позиционированного контейнера прокрутки. Иначе она расширяет layout viewport и мешает нажимать кнопки панели записи. Проверяется scrollWidth относительно clientWidth, а не innerWidth.

## Измерение модели

2026-10-28, Windows, Node v26.8.1: цепочка из 200 записей и 199 связей, три прогрева и десять запусков getHealth. Медиана 36.52 мс, диапазон 34.19–38.22 мс. Это локальный замер вычисления модели, без React/DOM; он не характеризует все браузеры и формы графа.

Воспроизводимый скрипт: `node scripts/benchmark-traceshelf.mjs` (Node 24+ с поддержкой TypeScript type stripping).

Визуально проверяются граф, таблица, панель причины и мобильный экран. Мобильная эмуляция не заменяет тестирование физических устройств и других движков.
